## 🔄 آلية عمل التقرير الجديد والتراكمي (Snapshot Inheritance)

> [!IMPORTANT]
> **كيفية عمل التقرير للشهر/الأسبوع الجديد:**
> 1. عند ضغط المستخدم على **"إنشاء تقرير الفترة الجديدة"** (مثلاً: شهر أغسطس):
> 2. يقوم النظام **تلقائياً بنسخ كامل بنود ونسب التقرير السابق** (شهر يوليو) كمسودة (`Draft`).
> 3. يقوم المستخدم فقط بتعديل البنود التي تم إنجاز أعمال إضافية فيها خلال هذا الشهر (مثلاً: زيادة نسب الأعمال من 30% إلى 50%).
> 4. يظل التقرير السابق محفوضاً كأرشيف تاريخي غير قابل للتعديل بالخطأ، ويقوم النظام بحساب **نسبة التقدم الشهري/الأسبوعي الصافي** (مثال: `+8% إنجاز إضافي هذا الشهر`).

## 🎯 الأهداف الرئيسية

1. **دعم التقارير التاريخية لكل مشروع (Multi-Snapshot Architecture):**
   - جدول `completion_reports` يربط بين المشروع `project_id` والفترة (`report_period`).
   - جلب قائمة كافة التقارير السابقة للمشروع وإتاحة اختيار أي فترة لمعاينتها أو مقارنتها.
2. **معالجة عدم وجود مشاريع (No Projects Fallback):**
   - توفير وضع التجربة (`Demo Mode`) وإنشاء سريع لمشروع جديد (`Quick Create Project Modal`).
3. **تصدير التقرير والطباعة (PDF Export / Print):**
   - طباعة وتصدير أي تقرير دوري كملف PDF رسمي.

## 📝 التغييرات المقترحة (Proposed Changes)

### 1. Backend (FastAPI & SQLAlchemy)
- `backend/app/models/completion_report.py`: دعم الحقول الزمانية وربط التقارير ببعضها (Parent Report ID).
- `backend/app/routers/completion_reports.py`: 
  - API جلب تقارير المشروع.
  - API مستحدث لـ `POST /api/v1/projects/{project_id}/completion-reports/clone-previous` لنسخ التقرير السابق تلقائياً للفترة الجديدة.

### 2. Frontend (React & Tailwind)
- `frontend/src/pages/CompletionPercentagePage.jsx`:
  - زر **"بدء تقرير فترة جديدة (مستنسخ من السلسلة)"**.
  - شريط تنقل بين فترات التقرير السابقة مع عرض نسبة الفارق.
