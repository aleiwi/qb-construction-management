# UI/UX Guidelines Skill

معايير تصميم تجربة المستخدم لنظام إدارة المقاولات، يلتزم بها UI/UX Agent و Frontend Agent.

## 1. مبدأ التصميم حسب الدور
كل دور مستخدم يشوف واجهة مختلفة تناسب مهامه فقط:
- **مدير المشروع**: Dashboard شامل (تقدم كل المشاريع، تنبيهات، ملخص مالي)
- **المهندس**: تركيز على تحديث نسب الإنجاز، رفع تقارير الموقع
- **المحاسب**: تركيز على المستحقات، الفواتير، التقارير المالية
- **المقاول**: واجهة مبسّطة جدًا — مشاريعه فقط، مستحقاته، حالة الدفعات

## 2. اللغة والاتجاه
- الواجهة بالكامل بالعربي مع دعم RTL (Right-to-Left) كامل
- الأرقام والتواريخ بصيغة واضحة (تفضيل الميلادي أو الهجري يُحدَّد لاحقًا من صاحب المشروع)

## 3. لوحات المعلومات (Dashboards)
- الأولوية لعرض بصري (رسوم بيانية، KPI cards) على الجداول الخام — نمط أثبت فعاليته سابقًا في تجارب مشابهة (ألوان واضحة تدل على الحالة: أخضر=مكتمل، أصفر=قيد التنفيذ، أحمر=متأخر)
- كل رقم مهم (نسبة إنجاز، مبلغ مستحق) يظهر بخط واضح وحجم بارز أعلى الصفحة

## 4. النماذج (Forms)
- التحقق الفوري من المدخلات (inline validation) قبل الإرسال
- رسائل الخطأ بالعربي وواضحة (تجنب رسائل تقنية مثل "Error 500")

## 5. الاستجابة (Responsiveness)
- رغم إن النطاق الحالي "ويب فقط"، التصميم يجب أن يكون متجاوبًا (responsive) على الأقل للتصفح من التابلت، لأن المهندسين والمقاولين غالبًا يستخدمون الموقع بالموقع الميداني

## 6. الاتساق البصري
- نظام ألوان وخطوط موحّد عبر كل الصفحات (design tokens) يحدده UI/UX Agent مرة واحدة ويلتزم فيه Frontend Agent بالكامل
- تجنب أي تصميم "افتراضي" يبدو مولّدًا آليًا دون هوية بصرية مميزة
