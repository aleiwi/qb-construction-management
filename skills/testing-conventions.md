# Testing Conventions Skill

معايير الاختبار الإلزامية قبل اعتماد أي ميزة في نظام إدارة المقاولات.

## 1. مستويات الاختبار
- **Unit Tests**: لكل دالة منطق عمل (خصوصًا حسابات المستحقات المرحلية والنسب المالية)
- **Integration Tests**: لكل API endpoint — التأكد من الاستجابة الصحيحة مع صلاحيات مختلفة
- **Edge Cases إلزامية**: نسبة إنجاز = 0%، نسبة إنجاز = 100%، مبالغ سالبة أو صفرية، مستخدم بدون صلاحية

## 2. تغطية الحسابات المالية
أي دالة تحسب مستحقات أو دفعات يجب أن تُختبر بحالات:
- دفعة جزئية (مثال: 40% من المرحلة)
- دفعة مكتملة
- محاولة دفع أكثر من المستحق (يجب أن تُرفض)

## 3. اختبار الصلاحيات (RBAC)
لكل endpoint، يُختبر:
- وصول مستخدم بالدور الصحيح → ينجح
- وصول مستخدم بدور غير مخوّل → يُرفض (403)
- وصول مقاول لبيانات مقاول آخر → يُرفض

## 4. معايير القبول
- لا يُدمج أي كود قبل اجتياز جميع الاختبارات (100% pass rate على الاختبارات الموجودة)
- أي ميزة مالية جديدة تتطلب حد أدنى من تغطية الاختبار قبل الاعتماد

## 5. بيانات الاختبار (Test Data)
- استخدام بيانات وهمية (mock data) مطابقة لسياق المقاولات (أسماء مشاريع، مقاولين تجريبيين) وليس بيانات عامة غير واقعية، لتسهيل اكتشاف الأخطاء المنطقية
