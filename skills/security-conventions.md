# Security Conventions Skill

معايير أمنية إلزامية يجب أن يطبقها أي Agent (Backend خصوصًا) في نظام إدارة المقاولات، نظرًا لحساسية البيانات المالية وبيانات المقاولين.

## 1. المصادقة (Authentication)
- كلمات المرور تُخزَّن مشفّرة فقط عبر bcrypt أو argon2 — ممنوع نهائيًا plaintext أو تشفير ضعيف (MD5/SHA1)
- استخدام JWT tokens لجلسات API مع مدة صلاحية محدودة (access token قصير + refresh token)

## 2. الصلاحيات (Authorization)
- كل endpoint يتحقق من صلاحية المستخدم **على مستوى الـ Backend** وليس الاعتماد على إخفاء الأزرار بالواجهة فقط
- المقاول يرى بياناته فقط (مبدأ Row-Level Security) — لازم يُفرض على مستوى الاستعلام (query)، لا يكفي فلترة بالواجهة

## 3. حماية من الثغرات الشائعة
- **SQL Injection**: استخدام ORM (مثل SQLAlchemy) مع parameterized queries حصرًا، ممنوع تركيب SQL كنص خام (raw string concatenation)
- **XSS**: تعقيم (sanitize) أي مدخل نصي يُعرض لاحقًا بالواجهة
- **CSRF**: حماية أي عملية تغيير حالة (POST/PUT/DELETE) بـ CSRF tokens إذا كان النظام يعتمد على cookies

## 4. رفع الملفات (File Uploads)
- فلترة الامتدادات المسموحة فقط (PDF, JPG, PNG, XLSX) ومنع أي ملف تنفيذي
- فحص حجم الملف قبل الرفع
- تخزين الملفات خارج مجلد التطبيق المباشر (لا يُنفَّذ كسكربت)

## 5. البيانات الحساسة
- بيانات مالية (مستحقات، رواتب) لا تُعرض في الـ logs أبدًا
- أي API key أو سر (secret) يُخزَّن في environment variables، ليس بالكود مباشرة

## 6. سجل التتبع (Audit Log)
- كل عملية مالية (دفعة، تعديل مستحق) تُسجَّل: من نفذها، متى، القيمة القديمة والجديدة

## 7. مراجعة دورية
- أي Pull Request يمس المصادقة أو الصلاحيات أو البيانات المالية يجب أن يمر على Cybersecurity Agent قبل الدمج، بدون استثناء
