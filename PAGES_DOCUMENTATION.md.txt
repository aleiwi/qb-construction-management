# PAGES_DOCUMENTATION.md — Quantum Build (نظام إدارة المقاولات المتكامل)

This document describes every page, route, component, and API integration in the current system.

---

## 1. Architecture Overview

- **Frontend:** React 18 + Vite + Tailwind CSS + Framer Motion + Recharts
- **Backend:** FastAPI + SQLAlchemy async + JWT (RBAC)
- **State Management:** React Context (useAuth) + local state + direct API calls via axios
- **Persistence:** PostgreSQL (via FastAPI); SQLite for dev/testing
- **Auth Flow:** JWT access token stored in localStorage; `ProtectedRoute` wrapper
- **Routing:** React Router v6 with lazy-loaded pages (code-splitting)
- **Error Handling:** Global `ErrorBoundary` wrapping all routes

## 3. Page Details

### 3.1 LoginPage (`/`)
- Route: `/` (root)
- Purpose: User authentication with JWT
- Features:
  - Email/password form with validation
  - 5 demo account quick-buttons (admin, pm, engineer, accountant, contractor)
  - Role-colored labels on demo buttons
  - Error handling via `react-hot-toast`
  - Redirects to `/dashboard` on success
- Auth: Uses `AuthContext.signIn()` calling `POST /api/v1/auth/login`

### 3.2 DashboardPage (`/dashboard`)
- Route: `/dashboard`
- Purpose: Central hub with role-specific views and admin panel
- Features:
  - User info header with role badge
  - Permission banner showing RBAC status (canManageUsers, canManageProjects, etc.)
  - Contractor restricted view notice (row-level security)
  - **Admin section:** User management table with create user form
  - **Module grid:** Cards linking to all 7 modules + reports + completion % + audit logs
  - Each card has unique color identity per module
- Auth: `ProtectedRoute` — requires valid JWT

### 3.3 ProjectsPage (`/projects`)
- Route: `/projects`
- Purpose: List and manage construction projects
- Features:
  - Project list with status badges
  - Create/edit project modal
  - Click navigates to `ProjectDetailPage`
- API: `projectsApi`

### 3.4 ProjectDetailPage (`/projects/:projectId`)
- Route: `/projects/:projectId`
- Purpose: View and manage a single project's buildings and stages
- Features:
  - Buildings list within the project
  - Stages per building with progress tracking
  - Weight percent management for stages
- API: `buildingsApi`, `stagesApi`

### 3.5 ContractorsPage (`/contractors`)
- Route: `/contractors`
- Purpose: Manage contractors and their specializations
- Features:
  - Contractor list with contact info
  - Create/edit contractor modal
  - Specialization tags (هدم, تربة, صحي, كهرباء, جبس, تهوية, حديد, إطفاء, واجهات, عزل)
  - Status tracking
- API: `contractorsApi`

### 3.6 ContractsPage (`/contracts`)
- Route: `/contracts`
- Purpose: Manage contracts linking contractors to buildings
- Features:
  - Contract list with status, value, retention %
  - Create/edit contract modal (contractor, building, title, value, retention, dates, status)
  - Status badges: draft (مسودة), active (نشط), completed (مكتمل), terminated (ملغي)
- API: `contractsApi`

### 3.7 DrawingsPage (`/drawings`)
- Route: `/drawings`
- Purpose: Upload and manage CAD drawings (DXF/DWG)
- Features:
  - Drag & drop file upload
  - Drawing list with auto-extraction status
  - Click to extract BOQ elements
- API: `boqApi`
- Backend: `ezdxf` library for CAD parsing

### 3.8 BOQReviewPage (`/boq-review`)
- Route: `/boq-review`
- Purpose: Manual review and classification of extracted BOQ elements
- Features:
  - Elements grouped by source layer
  - One-click classification buttons (جدار, عمود, بلاطة, كمرة, أساس, باب, نافذة, درج, سقف, حاجز, فتحة, أخرى)
  - Select/deselect all
  - Progress tracking of classified vs unclassified
- API: `boqApi`

### 3.9 PaymentsPage (`/payments`)
- Route: `/payments`
- Purpose: Financial payments and retention releases
- Features:
  - **Payments tab:** List payments by contract with approval/pay workflow
  - **Retentions tab:** List held retentions with release button
  - Contract selector to filter by contract
  - Payment amount, retention amount, net amount display
  - QC gate: approval blocked if stage QC not passed
- API: `paymentsApi`, `retentionsApi`

### 3.10 QualityChecksPage (`/quality-checks`)
- Route: `/quality-checks`
- Purpose: Quality inspection management
- Features:
  - Create QC inspections per stage
  - Pass/fail/pending status tracking
  - Inspector assignment
  - Mandatory gate before payment approval
- API: `qualityChecksApi`

### 3.11 EmployeesPage (`/employees`)
- Route: `/employees`
- Purpose: HR management — employees and attendance
- Features:
  - **Employees tab:** List, create, edit employees
  - **Attendance tab:** Daily attendance tracking (present/absent/leave)
  - Employee fields: name, national ID, phone, job title, monthly salary, hire date
  - Attendance with check-in/check-out times
- API: `employeesApi`

### 3.12 ReportsPage (`/reports`)
- Route: `/reports`
- Purpose: KPI dashboard with charts
- Features:
  - 6 KPI cards: Projects, Contractors, Payments, QC, Employees, BOQ
  - Radial bar chart for average progress
  - Pie charts for payment distribution and QC results
  - Bar charts for financial status and BOQ classification
  - Area chart for contracts overview
  - HR breakdown bar chart
  - All charts use Recharts with responsive containers
- API: `reportsApi` → `GET /api/v1/reports/kpis`

### 3.13 CompletionPercentagePage (`/completion-percentage`)
- Route: `/completion-percentage`
- Purpose: Comprehensive completion report with snapshot inheritance
- Features:
  - Project picker with quick-create for no-projects state
  - Historical report snapshots navigation bar
  - Clone previous report for new periods (Snapshot Inheritance)
  - Dashboard view (read-only report)
  - Edit view (progress input form)
  - Three progress indicators: structure, finishing, overall
  - Delta comparison with previous period
  - Save (create/update) to backend
  - Demo mode when no project selected
  - Confirm modals for reset and project switch
- Components: `ProgressInputForm`, `ProgressDashboard`, `NewPeriodModal`, `QuickCreateProjectModal`, `ConfirmModal`
- State: Tracks dirty/saving/saved/error/offline states
- API: `completionReportsApi` → CRUD + clone-previous

### 3.14 AuditLogsPage (`/audit-logs`)
- Route: `/audit-logs`
- Purpose: Full audit trail for financial operations
- Features:
  - Filter by entity type (payment, contract) and entity ID
  - Table with action, entity, user, old/new values, timestamp
  - JSON pretty-print for structured values
  - Admin-only access (redirects non-admin users)
- API: `GET /api/v1/audit-logs`

## 6. Design Conventions

- **All user-facing text is in Arabic**
- Code, logs, API fields, and comments are in English
- Dark theme with slate-950 background
- Cards use `bg-slate-900/80` with `border-slate-800`
- Each module has a unique accent color:
  - Dashboard: blue
  - Projects: indigo
  - Contractors: amber
  - Contracts: emerald
  - Drawings: indigo
  - Payments: purple
  - QC: teal
  - HR: rose
  - Reports: cyan
  - Completion: amber
  - Audit: orange
- Buttons use `rounded-xl` with hover transitions
- Loading states use spinner animation
- Modals use `backdrop-blur-sm` overlay
- All icons from `lucide-react`
- Animations via `framer-motion` (stagger, fade, scale)
